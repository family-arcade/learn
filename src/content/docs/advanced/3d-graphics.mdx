This page shows how we make good-looking 3D for the Family Arcade's games,
and keep it smooth on a tablet. It asks more of the grown-up: one part needs
a program on a computer.

## Two ways to make 3D

Start with the first.

**Shapes in code.** Claude builds characters and worlds from balls, boxes and
cones, with three.js: free code for 3D in a web browser. The starter template
allows it, bundled inside the game. It loads fast and works in Claude Code on
the web.

**Models made in Blender.** Blender is a free program for making 3D models.
Claude builds the model in it, and you put the file in your game. Use it for
shapes that simple pieces can't make, such as a ship.

  Gulp's whole city is shapes in code.

A 3D shape is made of small flat triangles. Fewer triangles draw faster, so
ask for a limit from the start:

<Prompt>Make the dragon 3D with three.js, from rounded shapes in code: a big head, a small body and two wings. Keep it under 3,000 triangles, with a test that checks it.</Prompt>

Shapes in code have limits. We tried twice to build a warship this way. One
try came out as a flat slab with a stick for a mast.

## Decide the look first

Pictures of how a character should look are called concept art. We make ours
in ChatGPT, on a grown-up's account, with the child beside us.

**Your child's part:**

- Draw the first shape on paper, for a photo.
- Name the character and pick four to six colours.
- Choose between two or three looks.
- Approve each picture before anything is built from it.

Keep each session to one loop that ends in play.

### Start with a character sheet

Write its name, three things about its shape, its colours, and what it must
never have. Reuse those words in every ask. Describe the look yourself,
without naming famous characters, films or living artists.

<Prompt label="In ChatGPT">Make concept art for a game character: Pip, a little dragon. Big round head, round body, stubby wings. Mint green, cream and coral. A chunky toy with flat colours. Plain background, no text. Pip never has scary teeth.</Prompt>

### Let your child pick

Ask for two or three looks. The picked picture is the reference for every
later picture.

<Prompt label="In ChatGPT">Make Pip in two other styles so we can choose: one hard and blocky, one soft and round like a plush toy.</Prompt>

### Ask for every side

<Prompt label="In ChatGPT">Use this picture of Pip as the reference. Show Pip from the front, side, back and three-quarter, the same size, in a row. Plain background, no text.</Prompt>

<Shot images={[{ src: conceptSheet, alt: 'A white chibi unicorn with a rainbow mane and pastel wings, from the front, side, back and three-quarter' }]}>
  Concept art for Rainbow Racer's unicorn, made with an AI image generator.
  Our children picked this look from five.
</Shot>

Ask for each view on its own if the views don't match. Change one thing at a
time, and say what must stay the same.

Concept art is a guide, not the finished model. Ours had more detail than a
racer needs, so we built two simpler versions in code. For every big change
to a game's look, we show the family about three labelled options like
these. We build the one they pick.

## Build a model in Blender

Claude works in Blender through the Blender Lab MCP Server, a free tool from
Blender's makers. MCP lets an AI helper use another program.

It runs on your own computer, with Blender open. So you need Claude Code on
that computer: in the Claude desktop app with a **Local** session, or in a
terminal. Claude Code on the web runs in the cloud and can't reach Blender.

<ArcadeDiagram which="blender" />

:::caution[Claude runs code inside Blender]
The MCP server runs code the AI writes, inside Blender, and nothing guards
your files. Blender warns that such code could delete them or send them
elsewhere. It suggests a computer without private files, or a virtual
machine, a separate computer inside yours. The grown-up decides, and stays at
the computer.
:::

### Set it up once

1. Install Blender 5.1 or newer, free from [blender.org](https://www.blender.org/download/).
2. Add the MCP add-on, an extra part for Blender, as
   [Blender's MCP Server page](https://www.blender.org/lab/mcp-server/)
   shows.
3. In Blender's preferences, under **System**, turn on **Allow Online
   Access**. The add-on needs it, and listens only to your own computer.
4. Ask Claude Code on the computer to connect it:

   <Prompt label="With Blender">Set up the official Blender Lab MCP Server, from blender.org/lab/mcp-server, for Claude Code on this computer. Explain each step before you run it.</Prompt>

5. Start a new session with Blender open.

### Build one model at a time

1. **Give Claude the picked concept art.** Drag it into the desktop app, or
   give the file's path in a terminal.
2. **Ask for one part, from simple shapes:**

   <Prompt label="With Blender">Look at the picture of Pip. In Blender, build only Pip's head and body from rounded shapes, and name them. Show us pictures from the front, three-quarter, side and back on white, then wait.</Prompt>

3. **Look at every side.** These pictures are called renders. On white,
   holes and gaps show up. Your child compares each side with the concept
   art.
4. **Change one thing at a time,** and say what must stay the same.
5. **Save it as a GLB,** one file with the model and its colours. Blender
   turns every face into triangles when it saves, so count the triangles in
   the GLB. Ask for few materials: a material is a surface's colour and
   finish.

   <Prompt label="With Blender">Get Pip ready for the game: feet on the ground, facing forward, parts named, as few materials as you can. Export pip.glb, and tell us its triangle count and file size.</Prompt>

:::note[Services that turn a picture into 3D]
Services such as Meshy or Tripo make a model from a picture. We haven't used
them for our games. Free plans often limit who owns the model, and some are
not meant for children. A grown-up reads the terms first.
:::

## Put a model in your game

The template's first rule is [nothing from other websites](/reference/rules/).
So the model goes into your repository, never loaded from another site.

1. Open your game's repository on GitHub.
2. Upload the model:
   1. Click **Add file**, then **Upload files**.
   2. Drag the GLB file onto the page.
   3. Choose **Commit directly to the main branch**.
   4. Click **Commit changes**.

   The file alone changes nothing in the game yet.
3. In Claude Code on the web, ask Claude to use it:

   <Prompt>I uploaded pip.glb. Use it for the dragon, bundled with the game, and compress it to keep the file small.</Prompt>

A compressed model needs a decoder, a little code to unpack it. three.js
includes one, so it stays inside the game too. The change goes live after the
merge.

## Keep it fast on a tablet

A game that runs smoothly on a computer can stutter on a tablet. Keep 3D
light from the start, and test on the real device.

- **Fewer triangles.** Each one is work for the tablet, in every frame.
- **Fewer pieces.** Each piece with its own material is a draw call: one job
  for the graphics chip, in every frame. Many pieces can cost more than many
  triangles. Join parts that move together, and paint the colours onto one
  material.
- **Small files.** Ship Battle's ships are 160 to 760 KB each. Our
  compression tool cut a 97,000-triangle test model from about 3 MB to 77 KB.
- **Simple light.** Use one main light, like the sun, and a soft fill, such
  as three.js's hemisphere light. A soft dark circle under a character is a
  cheap shadow. Add shadows and effects one at a time, and test each.
- **Not every pixel.** Tablet screens have two or three pixels per point. Our
  games draw at most two.

Rainbow Racer's racers are 2,000 to 3,000 triangles and four to six pieces
each, down from 18 to 60 pieces. A test holds the limit. Devices differ, so
measure on yours.

<Prompt>The game stutters on our iPad. Find what costs the most and count the triangles and draw calls. Explain it simply before you change anything.</Prompt>

Decide together when a fix makes the game look worse.

## Use only art you may use

A licence is a maker's rules for using their work. Use only models and
pictures you made, or that a licence allows.

- **No famous characters.** Don't start from downloaded models of famous
  characters, ships or vehicles, even changed ones.
- **Free to use:** [Kenney](https://kenney.nl/)'s game packs are free for any
  game, with no credit needed. Their licence is called CC0. Note the source
  anyway.
- **Credit when asked:** some models are free if you credit the maker. Their
  licence is called CC BY. List the maker, model, source and licence in your
  game's credits.
- **Check each model.** Free model sites often mix licences. Skip fan models,
  branded cars or ships, and anything without a licence.

## Skills that help with 3D

A skill is a file of instructions that Claude Code loads for one kind of
task. Claude follows it with the access Claude already has. So a grown-up
reads a skill before installing it, from a source they trust.

These three passed our check on 5 October 2026. They are free, use no paid
services, and add nothing from other websites to the game. A skill can change
after we checked it, so read it again when you install it.

- **threejs-aaa-graphics-builder** helps when your 3D still looks plain. It
  aims high, so tell it the game must stay smooth on your tablet.
- **threejs-debug-profiler** helps when the game stutters or the screen stays
  blank. It measures first, then fixes the biggest cost.
- **blender-image-to-3d** builds a Blender model from your concept art in
  steps. After each step it shows pictures and waits for your OK. It works
  with or without the MCP server. Its usual sizes are for computer games, so
  give it your triangle limit.

The first two are from Majid Manzarpour's
[three.js game skills](https://github.com/majidmanzarpour/threejs-game-skills).
Install only these two: others in that pack use paid services when given a
key. For Claude Code on the web, add them to your repository:

<Prompt>Copy the threejs-aaa-graphics-builder and threejs-debug-profiler skills from github.com/majidmanzarpour/threejs-game-skills into this repository's .claude/skills folder, and nothing else. Tell us simply what each one tells you to do.</Prompt>

After the merge, every new session loads them. The third is from the same
maker's [Blender game skills](https://github.com/majidmanzarpour/blender-game-skills).
It goes on the computer with Blender:

<Prompt label="With Blender">Install the blender-image-to-3d skill from github.com/majidmanzarpour/blender-game-skills in ~/.claude/skills. First tell us simply what it tells you to do.</Prompt>

Then start a new session.

## Rules for good 3D

1. Start with shapes in code.
2. Let your child pick the look from pictures, before building.
3. Build and change one thing at a time.
4. Check every side before you accept a model.
5. Keep pieces, triangles and materials few.
6. Test on the real tablet.
7. Use only art you may use, inside the game.
