The child says what the game should be. The grown-up types it. Start with one
sentence:

> Make a game where you are a dragon collecting gems in the clouds, for 1 to 4
> players. Keep play together working. Then run the tests.

Claude reads the starter and builds the game on a copy called a **branch**.
A branch lets you try a change without changing the main game. Claude runs
the tests and tells you what it did.

## Publish the change

A *pull request* is a request to put the change into your game. To *merge*
means to put the tested change into your game's main copy.

1. Wait until Claude says it is done.
2. Click **Create PR** to open a pull request. GitHub opens.
3. Merge the change:
   1. Click **Merge pull request**.
   2. Click **Confirm merge**.
4. Wait a minute or two for the change to be published:
   1. Click the <GhIcon name="play" />**Actions** tab.
   2. Look for a green dot next to the newest run.
5. Reload your game's page.

Your first game is on the web. That is the whole loop:

**Ask → merge → play.**

Everything you do from now on is this loop again.

:::tip[Before you merge]
If something is not right, say so: "The dragon is too small, make it
bigger." Claude changes it on the same branch. Merge once it is right.
:::
